# 其他设备部署与使用说明

本文用于在一台新的 Windows 设备上部署并运行 Agent Guard，包括 OpenClaw 对话监督、Docker 隔离检测和 5/30 用例黑盒验收。

## 1. 准备环境

安装以下软件：

- Git
- Docker Desktop，并切换到 Linux 容器
- Windows PowerShell 5.1 或 PowerShell 7
- Node.js `>=22.22.3 <23`、`>=24.15.0 <25` 或 `>=25.9.0`

检查环境：

```powershell
git --version
node --version
npm --version
docker version
```

`docker version` 必须能同时返回 Client 和 Server 信息。只安装 Docker CLI、没有启动 Docker Desktop，无法运行检测。

## 2. 获取项目

当前完整功能位于 `feat/openclaw-native-tool-guard` 分支：

```powershell
git clone -b feat/openclaw-native-tool-guard https://github.com/wuyang39/agent-guard.git
cd agent-guard
```

如果该分支已经合并到默认分支，直接克隆默认分支即可。

项目使用的两个外部产物已经公开，不需要手工下载：

```text
OpenClaw fork:
https://github.com/wuyang39/openclaw-agentguard

固定 commit:
0cd158ce32d5c53daee74235cf0557fc4d414b17

Docker 镜像:
ghcr.io/wuyang39/openclaw-sandbox@sha256:01630cbb3486af7c0908b326d956d20722fde3ceada2775b53e547370a4e0e38
```

这些值也记录在 `configs/openclaw-distribution.json`。不要改成 `latest` 或其他可变 tag。

## 3. 初始化运行环境

在仓库根目录运行：

```powershell
npm run openclaw:bootstrap
```

脚本会自动完成以下工作：

1. 安装 Agent Guard 依赖。
2. 克隆并校验固定版本的 OpenClaw fork。
3. 构建 OpenClaw 和 Agent Guard 监督插件。
4. 拉取固定 digest 的 Docker 镜像。
5. 创建独立 OpenClaw profile 并安装插件。
6. 生成本机环境文件 `outputs/agent-guard-openclaw-env.ps1`。

OpenClaw profile 位于：

```text
%USERPROFILE%\.agent-guard\openclaw-native-guard-profile
```

它不在 Git 仓库中。模型凭据、Gateway token、运行日志和测试输出都不会提交到远程库。

## 4. 配置模型

每台设备需要单独配置一次模型提供商：

```powershell
. .\outputs\agent-guard-openclaw-env.ps1
node $env:OPENCLAW_CLI configure
```

配置完成后检查：

```powershell
node $env:OPENCLAW_CLI models status --json --check
```

命令退出码为 `0` 才表示当前模型和凭据可以使用。不要把 API Key 写入项目的 `.env`、文档或测试证据。

## 5. 启动和停止

启动完整系统：

```powershell
npm run openclaw:start
```

脚本会启动四个服务：

| 服务 | 地址 |
|---|---|
| Agent Guard 前端 | `http://127.0.0.1:5173` |
| Agent Guard API | `http://127.0.0.1:3100/api/v1/system/status` |
| OpenClaw 对话界面 | `http://127.0.0.1:18789` |
| Sample Agent | `http://127.0.0.1:7001/health` |

OpenClaw 对话 Gateway 由 `openclaw-guard-launcher.ts` 启动。检测任务会使用另一套按 RunGroup 创建的隔离 Gateway，不会把对话 Gateway 当作检测信任根。

停止系统：

```powershell
npm run openclaw:stop
```

重新执行 bootstrap 前应先停止系统，否则 Windows 可能因为 `esbuild.exe` 正在使用而拒绝 `npm ci` 更新文件。

## 6. 检查系统状态

启动后运行：

```powershell
Invoke-RestMethod http://127.0.0.1:3100/api/v1/system/status
```

返回结果应包含：

```text
ok: true
health.api: true
health.openclawCli: true
features.openclawAdapter: true
features.openclawNativeGuard: true
```

Native Guard 没有激活 lease 时，插件显示 `coverage=off`、后端控制面显示 `coverage=ready` 都是正常空闲状态。此时插件不会干预普通 OpenClaw 对话。

后端启动后会在后台运行一次只读的宿主 capability 预热。受控 fork 第一次执行 `plugins list --json --live` 可能需要 30 到 60 秒，但不会阻塞 API、前端或 Guard OFF 的普通 OpenClaw 使用。预热完成后，重复 status/activate 通常只需毫秒级时间。结果在后端进程内缓存五分钟，并按 active agent、CLI、Gateway URL 和 OpenClaw profile 路径隔离；控制请求失败、身份变化或后端重启都会清空对应结果。Docker 检测使用独立的 run-scoped capability snapshot，不读取这份宿主缓存。

手工从当前 PowerShell 调用已启动的 Gateway 时，还需要注入启动脚本生成的本地凭据：

```powershell
. .\outputs\agent-guard-openclaw-env.ps1
$env:OPENCLAW_GATEWAY_URL = "http://127.0.0.1:18789"
$env:OPENCLAW_GATEWAY_TOKEN = (Get-Content -Raw .\outputs\runtime\openclaw-gateway-token.txt).Trim()
node $env:OPENCLAW_CLI agent --session-key agent:main:demo --message "hello" --json
```

不要输出、提交或复制 token 文件内容。停止并重新启动系统后，应重新从 runtime 文件注入当前 token。

## 7. 运行验证

先运行本地合约和真实环境检查：

```powershell
. .\outputs\agent-guard-openclaw-env.ps1
npm run test:openclaw:portable
npm run verify:native-guard:real
npm run verify:native-guard:docker -- --required
```

快速检查 5 个用例：

```powershell
npm run verify:openclaw:load -- --case-counts=5
```

正式执行严格的 `5 -> 30` 黑盒验收：

```powershell
npm run verify:openclaw:load
```

脚本只会在 5 用例 RunGroup 完成且 Docker 资源清理干净后创建 30 用例 RunGroup。任一阶段失败都会立即停止，不会用新的 RunGroup 覆盖失败记录。

验收证据保存在：

```text
outputs/runs/portable-load-*.jsonl
```

完整工程回归：

```powershell
npm run verify:all
```

## 8. 日常更新

更新当前功能分支：

```powershell
npm run openclaw:stop
git pull
npm run openclaw:bootstrap
npm run openclaw:start
```

bootstrap 会检查 fork commit、buildstamp 和 Docker digest。OpenClaw fork 中存在未提交修改时，脚本会停止，不会覆盖本地文件。

## 9. 常见问题

### Docker daemon 不可用

确认 Docker Desktop 已启动，并等待状态变为 Running：

```powershell
docker version
```

### `AGENT_GUARD_DETECTION_IMAGE` 未设置

重新运行 bootstrap，并在当前终端加载环境文件：

```powershell
npm run openclaw:bootstrap
. .\outputs\agent-guard-openclaw-env.ps1
```

通过网页启动检测时，环境变量由后台服务继承，因此修改环境后需要重启系统。

### `models status --check` 失败

当前设备没有可用的模型凭据，或原凭据已经失效：

```powershell
. .\outputs\agent-guard-openclaw-env.ps1
node $env:OPENCLAW_CLI configure
```

### 端口已被占用

先停止之前由本项目启动的进程：

```powershell
npm run openclaw:stop
```

如果仍然占用，检查端口对应的进程：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 3100,5173,7001,18789 |
  Select-Object LocalPort,OwningProcess
```

不要直接复用来源不明的 Gateway 或后端进程。

### `EPERM ... esbuild.exe`

前端或后端还在使用 Node 依赖。运行 `npm run openclaw:stop`，确认四个端口已经释放，再重新执行 bootstrap。

### 检测运行很慢

OpenClaw 检测当前按顺序执行，每个 case 都要完成模型调用、证据调和、容器证明和清理。先用 5 用例确认环境。遇到 provider 限流或超时时，查看：

```text
outputs/runs/portable-services/backend.stderr.log
outputs/runs/portable-load-*.jsonl
```

不要在 coverage reconciliation 缺失时直接重跑并忽略原失败。

## 10. 新设备验收清单

- [ ] Docker Client 和 Server 均可用。
- [ ] bootstrap 执行成功。
- [ ] `models status --json --check` 退出码为 0。
- [ ] 四个服务地址均可访问。
- [ ] Native Guard 空闲时为 `coverage=off`。
- [ ] real registry gate 通过。
- [ ] required Docker gate 通过。
- [ ] 5 用例完成，coverage breach 为 0。
- [ ] 30 用例完成并达到 `coverage=active`。
- [ ] 两个 RunGroup 结束后均无 Docker 容器和网络残留。
